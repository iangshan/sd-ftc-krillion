# Website project instructions

Build a visually coherent, responsive website that is easy to maintain in GitHub.

## Design and accessibility

- Use the project brief and any supplied brand assets or Figma designs to guide layout, typography, color, and imagery.
- Make navigation and primary actions easy to find. Use consistent spacing, type, and component styles across pages.
- Use semantic HTML, visible keyboard focus, sufficient color contrast, and descriptive text alternatives for meaningful images. Label form fields and make errors easy to understand.

## Code and repository

- Follow the existing framework, package manager, and folder conventions. For a new project, choose the simplest stack that meets the site's requirements.
- Keep pages, shared components, styles, and assets easy to find. Reuse components and design tokens where they make the site easier to update.
- Keep the README current with setup, local development, build, and any configured deployment instructions. Keep secrets out of version control.

## Verification and review

- Run the relevant build, lint, and test commands already defined by the project.
- Preview changed pages on mobile and desktop. Check navigation, keyboard interaction, and any forms or other flows affected by the change.
- When submitting changes to GitHub, use a focused branch and a reviewable pull request. Include what changed, which checks ran, and screenshots for meaningful visual changes.
